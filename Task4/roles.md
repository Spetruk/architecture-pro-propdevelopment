# Ролевая модель RBAC для PropDevelopment Kubernetes

## Таблица ролей и полномочий

| Роль | Права роли | Группы пользователей |
| --- | --- | --- |
| **admin-full** | • Полный доступ ко всем ресурсам кластера<br>• Создание/удаление namespace<br>• Управление RBAC ролями<br>• Доступ к секретам всех доменов<br>• Управление узлами кластера<br>• Просмотр метрик и логов | • Системные администраторы<br>• DevOps инженеры<br>• Архитекторы системы |
| **domain-sales-admin** | • Полный доступ к namespace `sales`<br>• Создание/обновление Deployments, Services, ConfigMaps<br>• Доступ к секретам домена продаж<br>• Просмотр логов приложений домена<br>• Управление ресурсами (CPU, память) | • DevOps домена продаж<br>• Старшие разработчики домена продаж |
| **domain-tenant-admin** | • Полный доступ к namespace `tenant-services`<br>• Управление сервисами ЖКУ<br>• Доступ к секретам smart-home интеграций<br>• Конфигурация API Gateway настроек<br>• Управление подключениями к внешним системам | • Инженеры умного дома<br>• DevOps домена ЖКУ |
| **domain-finance-admin** | • Полный доступ к namespace `finance`<br>• Управление финансовыми сервисами<br>• Доступ к секретам финансовых интеграций<br>• Конфигурация подключений к банкам<br>• Управление хранилищем данных | • Финансовые аналитики<br>• Команда бухгалтерии<br>• DevOps финансового домена |
| **developer** | • Создание/обновление Deployments в назначенных namespace<br>• Просмотр логов своих приложений<br>• Создание ConfigMaps (без секретов)<br>• Просмотр статуса подов<br>• Доступ к метрикам приложений | • Разработчики всех доменов<br>• QA инженеры<br>• Junior DevOps |

## Принципы разграничения доступа

### По доменной структуре PropDevelopment:
- **Домен продаж**: Отдельные права для управления сервисами витрины, CRM клиентов, онлайн-сделок
- **Домен ЖКУ**: Специальные права для управления умным домом и интеграциями с партнерами
- **Домен финансов**: Изолированный доступ к финансовым данным и аналитике

### По принципу минимальных привилегий:
- Каждая роль имеет только необходимые права для выполнения рабочих задач
- Доступ к секретам ограничен соответствующими доменами
- Разделение между read-only и administrative доступом

### По организационной иерархии:
- Системные администраторы имеют полный доступ
- Доменные администраторы управляют только своими областями
- Разработчики имеют ограниченные права в рамках своих проектов
